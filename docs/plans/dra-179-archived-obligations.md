# DRA-179 archived-obligation reconciliation

Scope: map retained archived behavior to current public owners and stable issue IDs without promoting deleted-page art to policy. This is a contract disposition, not implementation or visual acceptance.

Failure cases: an archived illustration silently authorizes posting or payment; one task appears in two queues; a client shell grants accountant authority; an unsupported source/rule is reported as complete; an absent archive item is marked reconciled; a candidate K-board is reported as adopted.

Acceptance: every mapped obligation below names a current owner and its open decision or proof; inaccessible historical issue bodies remain explicitly unresolved. No baseline, threshold, manifest, seed, UI or financial operation changes.

## Shared refusal and proof boundary

A bureau or client route may project the same scoped task, but cannot duplicate its action or receipt owner. Financial amounts come from stored records; posting consumes the sealed revision under current authority and records one atomic receipt. Source and rule gaps remain visible and block dependent acts. Approval of a financial change does not authorize a payment, external message or filing. Unknown external outcomes need reconciliation before retry. Each current owner must verify its normal HTTP/MCP/browser path using isolated synthetic data, and separately record visual baseline/actual/diff for any adopted screen. This document supplies neither archived-body coverage nor that evidence.

Decision blockers: obtain the exact DRA-137/138/139 and DRA-179 issue bodies plus private archived obligation inventory through an authorized read-only review; decide any unmatched obligation with the responsible owner, and record the disposition against its stable ID. Accept ADR 0019 before treating client/founder navigation as adopted. Do not close DRA-179 on this provisional mapping alone.
