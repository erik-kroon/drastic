# Evaluation input contracts

The first evaluation unit retains immutable input identities for an operator. Packet 2 remains incomplete. Contract capture does not begin a candidate run, distribute original bytes, hold an accountant reference or freeze a result.

`POST /api/v1/entities/:entityId/books/:bookId/evaluations/contracts` captures selected retained original IDs, server-read original descriptors and hashes, a declared date interval, the existing company-profile owner's resolutions, explicit unknown opening and family population, permitted assistance and a validated capability-name inventory. Requests cannot supply authoritative financial amounts or claim complete coverage. Profile resolution uses the start date for posting, tax-point and payment selectors and the end date for report and tax-period selectors. These observations do not prove continuous interval coverage or settle missing company facts.

Capture and `GET .../evaluations/contracts/:id` require current operator authority. Both capabilities have `agentCallable: false`. The retained assistance and capability policy is a declaration, with no enforcement claim. Candidate enrollment, private reference custody, shared-input distribution receipts, assistance reconciliation, incomplete freeze, complete year pack and reviewed outputs remain later units.

The application transaction takes the existing book update lock before capture and replay. The source projection preserves the retained-source owner's read-access checks, and the profile resolver shares that transaction. Original hashes are the source owner's retained identity, not proof that an external object remains available or that either participant received its bytes. Exact operation, actor, input and key replay returns the committed contract. Changed actor or input conflicts. Expired or revoked authority cannot recover a success through replay.

A correction supplies the predecessor ID and expected digest to capture a new contract. The predecessor remains immutable. A book-scoped uniqueness constraint permits one accepted successor per predecessor. Migration `0049-evaluation-contracts.sql` adds only the immutable contract table and SELECT/INSERT runtime grants.

The existing recovery inventory discovers permanent tables, hashes their rows and checks applied migrations and schema identity. Evaluation rows contain retained descriptors without external object keys. The synthetic recovery E2E includes a nonempty evaluation row and checks exact rediscovery after dump/restore. The separate strict schema inventory probe is not qualified. It refuses the existing unvalidated `vat_assessment_receipts_match_fkey` introduced by migration 0031. The recovery fixture records exact restored rows before removing its diagnostic `pg_stat_statements` extension, then preserves identical full table fingerprints and checks JSON closure. This fixture normalization is not exact schema equality with the instrumented source. Constraint validation remains a separate forward-migration unit. Application recovery admission is still deferred to its own owner. This unit does not implement packet 3 or establish production recovery.
