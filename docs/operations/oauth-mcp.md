# OAuth MCP authorization

Owner: authentication and database admission. Audience: a signed-in bureau operator authorizing an OAuth client to read one linked book. This is a synthetic application qualification, not production onboarding or provider approval.

The immutable grant fixes actor, bureau and book. Current active firm membership, linked client book, operator membership and enabled identity must remain valid. Later memberships cannot widen the ceiling. Each MCP transaction locks and rechecks the token, grant and live authority; expiry is read after potentially blocking locks. Revocation locks the same grant before appending its refusal. Refresh is serialized by authorization family and checks live grant authority. Read-only discovery and invocation use the same catalog; no prepare, approve, execute or delivery tools are exposed. OAuth tokens are refused by ordinary HTTP owners. Existing API credentials and browser sessions keep their own authority paths.

Before consent UI implementation, retain these failure cases: no preselected bureau or book; unavailable or removed client prevents selection; signed query is lost during login or selection; displayed client differs from the signed authorization request; refresh/reload loses the retained book; consent submits without the retained grant; denial issues a code; unexpected redirect origin is followed before provider validation; expired or revoked authority still offers an enabled action; interrupted selection invents success; an old selection response overwrites a newer choice; token, verifier, cookie or authorization code appears in public evidence.

Independently read journals stay unchanged. Only credential-free observations may be retained publicly.

Local acceptance: the API workflow also verifies ordinary password accounts with no explicit admission row, then inserts an explicit disabled identity and observes refusal. Actor and existing identity rows are locked before grant/authority admission, matching the provisioning owner's actor lock and canonical enabled-by-default rule. The browser preserves the raw signed authorization query; router-normalised repeated parameters cannot be used for continuation.

The selected ceiling is immutable for one browser sign-in session. Retrying the same retained selection continues safely. Another ceiling requires a new sign-in; it cannot silently widen an existing token. Revocation is available through the authenticated owner endpoint. A grant-management screen, production registration policy, live clients and deployment qualification are outside these adopted targets.
